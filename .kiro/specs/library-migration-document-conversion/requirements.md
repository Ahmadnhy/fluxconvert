# Requirements Document

## Introduction

This document specifies requirements for migrating the document conversion feature to use higher-quality conversion libraries. The current implementation uses mammoth.js + pdf-lib for Word-to-PDF conversion and pdf2json + docx for PDF-to-Word conversion, which only support basic text extraction. The new implementation will use LibreOffice CLI for Word-to-PDF conversion and pdf2docx for PDF-to-Word conversion to preserve formatting, images, tables, and other document elements.

## Glossary

- **Conversion_Service**: The Next.js API route handlers that process document conversion requests
- **LibreOffice_Converter**: The LibreOffice command-line interface used for Word-to-PDF conversion
- **Pdf2docx_Converter**: The pdf2docx Python library used for PDF-to-Word conversion
- **Input_File**: The original document file uploaded by the user for conversion
- **Output_File**: The converted document file generated by the Conversion_Service
- **Storage_Service**: Supabase storage buckets that store uploaded and converted files
- **Database_Service**: Supabase database that tracks conversion records and file metadata
- **Authenticated_User**: A user who has logged in and has a valid user ID
- **Anonymous_User**: A user who has not logged in and has no user ID
- **Conversion_Record**: A database entry tracking the conversion status and associated files
- **File_Size_Limit**: The maximum allowed file size of 50 MB
- **Temporary_File**: A file created during conversion processing that must be cleaned up after use
- **Conversion_History**: The dashboard component that displays a user's past conversion records
- **Delete_Button**: A UI button that allows users to remove individual conversion history entries
- **Confirmation_Dialog**: A modal dialog that asks users to confirm destructive actions
- **Placeholder_Text**: The hint text displayed in input fields and dropdowns when no value is selected
- **Horizontal_Scrollbar**: A scrollbar that appears at the bottom of the page when content exceeds viewport width

## Requirements

### Requirement 1: Word-to-PDF Conversion with LibreOffice

**User Story:** As a user, I want to convert Word documents to PDF using LibreOffice, so that I can preserve formatting, images, tables, and other document elements.

#### Acceptance Criteria

1. WHEN a valid .docx file is uploaded to the Word-to-PDF endpoint, THE Conversion_Service SHALL use the LibreOffice_Converter to generate a PDF file
2. THE LibreOffice_Converter SHALL preserve text formatting including fonts, sizes, colors, bold, italic, and underline
3. THE LibreOffice_Converter SHALL preserve images with their original positioning and sizing
4. THE LibreOffice_Converter SHALL preserve tables with their structure, borders, and cell formatting
5. THE LibreOffice_Converter SHALL preserve page layout including margins, headers, and footers
6. WHEN the LibreOffice_Converter completes successfully, THE Conversion_Service SHALL return the Output_File to the user
7. IF the LibreOffice_Converter fails, THEN THE Conversion_Service SHALL return a descriptive error message

### Requirement 2: PDF-to-Word Conversion with pdf2docx

**User Story:** As a user, I want to convert PDF documents to Word using pdf2docx, so that I can preserve formatting, images, tables, and other document elements.

#### Acceptance Criteria

1. WHEN a valid .pdf file is uploaded to the PDF-to-Word endpoint, THE Conversion_Service SHALL use the Pdf2docx_Converter to generate a Word file
2. THE Pdf2docx_Converter SHALL preserve text formatting including fonts, sizes, colors, bold, italic, and underline
3. THE Pdf2docx_Converter SHALL preserve images with their original positioning and sizing
4. THE Pdf2docx_Converter SHALL preserve tables with their structure, borders, and cell formatting
5. THE Pdf2docx_Converter SHALL preserve page layout including margins and spacing
6. WHEN the Pdf2docx_Converter completes successfully, THE Conversion_Service SHALL return the Output_File to the user
7. IF the Pdf2docx_Converter fails, THEN THE Conversion_Service SHALL return a descriptive error message

### Requirement 3: LibreOffice Installation and Configuration

**User Story:** As a system administrator, I want LibreOffice to be properly installed and configured, so that the Word-to-PDF conversion can execute successfully.

#### Acceptance Criteria

1. THE Conversion_Service SHALL verify that LibreOffice is installed before attempting conversion
2. IF LibreOffice is not installed, THEN THE Conversion_Service SHALL return an error message indicating missing dependency
3. THE Conversion_Service SHALL execute LibreOffice in headless mode without requiring a display server
4. THE Conversion_Service SHALL specify the output format as PDF when invoking LibreOffice
5. THE Conversion_Service SHALL specify the output directory when invoking LibreOffice

### Requirement 4: Python and pdf2docx Installation

**User Story:** As a system administrator, I want Python and pdf2docx to be properly installed, so that the PDF-to-Word conversion can execute successfully.

#### Acceptance Criteria

1. THE Conversion_Service SHALL verify that Python is installed before attempting conversion
2. THE Conversion_Service SHALL verify that the pdf2docx library is installed before attempting conversion
3. IF Python or pdf2docx is not installed, THEN THE Conversion_Service SHALL return an error message indicating missing dependency
4. THE Conversion_Service SHALL execute pdf2docx conversion through a Python subprocess
5. THE Conversion_Service SHALL pass the input file path and output file path to the Python subprocess

### Requirement 5: Temporary File Management

**User Story:** As a system operator, I want temporary files to be properly managed, so that disk space is not exhausted and security is maintained.

#### Acceptance Criteria

1. WHEN the Conversion_Service receives an Input_File, THE Conversion_Service SHALL write it to a Temporary_File with a unique name
2. THE Conversion_Service SHALL store Temporary_Files in a dedicated temporary directory
3. WHEN the LibreOffice_Converter or Pdf2docx_Converter completes, THE Conversion_Service SHALL read the Output_File from the temporary directory
4. WHEN the Output_File has been uploaded to the Storage_Service, THE Conversion_Service SHALL delete all Temporary_Files associated with that conversion
5. IF an error occurs during conversion, THEN THE Conversion_Service SHALL delete all Temporary_Files associated with that conversion
6. THE Conversion_Service SHALL generate unique Temporary_File names using timestamps and random identifiers to prevent collisions

### Requirement 6: Backward Compatibility with Existing API

**User Story:** As a frontend developer, I want the API endpoints to maintain the same interface, so that existing client code continues to work without modification.

#### Acceptance Criteria

1. THE Conversion_Service SHALL maintain the existing POST endpoint at /api/convert/word-to-pdf
2. THE Conversion_Service SHALL maintain the existing POST endpoint at /api/convert/pdf-to-word
3. THE Conversion_Service SHALL accept multipart/form-data with a file field named "file"
4. THE Conversion_Service SHALL return JSON responses with the same structure as the current implementation
5. THE Conversion_Service SHALL include success, fileName, fileSize, downloadUrl, and optional expiresAt fields in successful responses
6. THE Conversion_Service SHALL return error responses with an error field containing a descriptive message

### Requirement 7: File Size Validation

**User Story:** As a system operator, I want file size limits to be enforced, so that the system is not overwhelmed by excessively large files.

#### Acceptance Criteria

1. WHEN an Input_File is uploaded, THE Conversion_Service SHALL validate that the file size does not exceed the File_Size_Limit
2. IF the Input_File exceeds the File_Size_Limit, THEN THE Conversion_Service SHALL return an error message without attempting conversion
3. THE File_Size_Limit SHALL remain 50 MB for both Word-to-PDF and PDF-to-Word conversions

### Requirement 8: File Type Validation

**User Story:** As a user, I want to receive clear error messages for unsupported file types, so that I understand what files are accepted.

#### Acceptance Criteria

1. WHEN a file is uploaded to the Word-to-PDF endpoint, THE Conversion_Service SHALL validate that the file extension is .docx
2. IF the file extension is not .docx, THEN THE Conversion_Service SHALL return an error message indicating only .docx files are supported
3. WHEN a file is uploaded to the PDF-to-Word endpoint, THE Conversion_Service SHALL validate that the file extension is .pdf
4. IF the file extension is not .pdf, THEN THE Conversion_Service SHALL return an error message indicating only .pdf files are supported

### Requirement 9: Storage and Database Integration

**User Story:** As an authenticated user, I want my conversions to be tracked in the database, so that I can view my conversion history.

#### Acceptance Criteria

1. WHEN an Authenticated_User uploads an Input_File, THE Conversion_Service SHALL create a file record in the Database_Service
2. WHEN an Authenticated_User uploads an Input_File, THE Conversion_Service SHALL upload the Input_File to the Storage_Service uploads bucket
3. WHEN an Authenticated_User initiates a conversion, THE Conversion_Service SHALL create a Conversion_Record with pending status
4. WHEN the conversion completes successfully, THE Conversion_Service SHALL update the Conversion_Record status to completed
5. WHEN the conversion completes successfully, THE Conversion_Service SHALL upload the Output_File to the Storage_Service converted bucket
6. WHEN the conversion completes successfully, THE Conversion_Service SHALL create a file record for the Output_File
7. WHEN the conversion completes successfully, THE Conversion_Service SHALL update the Conversion_Record with the output file ID
8. IF the conversion fails, THEN THE Conversion_Service SHALL update the Conversion_Record status to failed with an error message

### Requirement 10: Anonymous User Support

**User Story:** As an anonymous user, I want to convert documents without logging in, so that I can quickly test the service.

#### Acceptance Criteria

1. WHEN an Anonymous_User uploads an Input_File, THE Conversion_Service SHALL process the conversion without requiring authentication
2. WHEN an Anonymous_User uploads an Input_File, THE Conversion_Service SHALL upload the Input_File to the Storage_Service with an "anonymous" prefix in the storage path
3. WHEN an Anonymous_User conversion completes, THE Conversion_Service SHALL return the Output_File as a base64-encoded data URL
4. THE Conversion_Service SHALL NOT create a Conversion_Record for Anonymous_User conversions

### Requirement 11: Signed URL Generation for Authenticated Users

**User Story:** As an authenticated user, I want to receive a secure download link, so that I can download my converted file.

#### Acceptance Criteria

1. WHEN an Authenticated_User conversion completes successfully, THE Conversion_Service SHALL generate a signed URL for the Output_File
2. THE signed URL SHALL expire after 3600 seconds (1 hour)
3. THE Conversion_Service SHALL return the signed URL in the downloadUrl field
4. THE Conversion_Service SHALL return the expiration timestamp in the expiresAt field
5. IF signed URL generation fails, THEN THE Conversion_Service SHALL fall back to returning a base64-encoded data URL

### Requirement 12: Error Handling and Logging

**User Story:** As a system operator, I want detailed error logs, so that I can diagnose and resolve conversion failures.

#### Acceptance Criteria

1. WHEN an error occurs during conversion, THE Conversion_Service SHALL log the error message with relevant context
2. WHEN an error occurs during conversion, THE Conversion_Service SHALL return a user-friendly error message
3. THE Conversion_Service SHALL log successful conversions with input and output file paths
4. THE Conversion_Service SHALL log file upload operations with storage paths and file record IDs
5. THE Conversion_Service SHALL log Conversion_Record creation and status updates

### Requirement 13: Conversion Timeout Handling

**User Story:** As a system operator, I want conversions to timeout after a reasonable duration, so that hung processes do not consume resources indefinitely.

#### Acceptance Criteria

1. WHEN the LibreOffice_Converter is invoked, THE Conversion_Service SHALL set a timeout of 120 seconds
2. WHEN the Pdf2docx_Converter is invoked, THE Conversion_Service SHALL set a timeout of 120 seconds
3. IF a conversion exceeds the timeout, THEN THE Conversion_Service SHALL terminate the conversion process
4. IF a conversion exceeds the timeout, THEN THE Conversion_Service SHALL return an error message indicating timeout
5. IF a conversion exceeds the timeout, THEN THE Conversion_Service SHALL clean up all Temporary_Files

### Requirement 14: Removal of Legacy Libraries

**User Story:** As a developer, I want legacy conversion libraries to be removed, so that the codebase is clean and maintainable.

#### Acceptance Criteria

1. THE Conversion_Service SHALL NOT use mammoth.js for Word-to-PDF conversion
2. THE Conversion_Service SHALL retain pdf-lib library for potential future PDF manipulation features
3. THE Conversion_Service SHALL NOT use pdf2json for PDF-to-Word conversion
4. THE Conversion_Service SHALL NOT use the docx library for PDF-to-Word conversion
5. THE package.json file SHALL NOT include mammoth, pdf2json, or docx as dependencies after migration
6. THE package.json file SHALL retain pdf-lib as a dependency

### Requirement 15: Deployment Configuration

**User Story:** As a DevOps engineer, I want deployment configuration to include all required dependencies, so that the application runs correctly in production.

#### Acceptance Criteria

1. THE deployment configuration SHALL include instructions for installing LibreOffice
2. THE deployment configuration SHALL include instructions for installing Python 3
3. THE deployment configuration SHALL include instructions for installing pdf2docx via pip
4. WHERE the application is deployed on Vercel, THE deployment configuration SHALL specify the required system packages in vercel.json
5. THE deployment configuration SHALL document the minimum versions for LibreOffice, Python, and pdf2docx

### Requirement 16: Fix Pending Status Display in Conversion History

**User Story:** As a user, I want to see the correct status for my conversions, so that I understand which conversions are still processing.

#### Acceptance Criteria

1. WHEN a conversion has status "pending", THE Conversion_History SHALL display a yellow badge with "Pending" label
2. WHEN a conversion has status "processing", THE Conversion_History SHALL display a blue badge with "Processing" label
3. WHEN a conversion has status "completed", THE Conversion_History SHALL display a green badge with "Completed" label
4. WHEN a conversion has status "failed", THE Conversion_History SHALL display a red badge with "Failed" label
5. THE status badge SHALL be clearly visible and distinguishable from other badges
6. THE Conversion_History SHALL fetch and display the actual status from the database without client-side status manipulation

### Requirement 17: Delete Conversion History Entry

**User Story:** As a user, I want to delete individual conversion history entries, so that I can manage my conversion history and remove unwanted entries.

#### Acceptance Criteria

1. WHEN viewing the Conversion_History, THE user SHALL see a delete button in the top-right corner of each conversion entry
2. WHEN the user clicks the delete button, THE Conversion_History SHALL display a confirmation dialog asking "Are you sure you want to delete this conversion?"
3. WHEN the user confirms deletion, THE Conversion_History SHALL send a DELETE request to the API endpoint
4. WHEN the deletion is successful, THE Conversion_History SHALL remove the entry from the display without requiring a page refresh
5. WHEN the deletion fails, THE Conversion_History SHALL display an error message to the user
6. THE delete button SHALL be styled with a red color to indicate destructive action
7. THE delete button SHALL show a trash icon for clear visual indication
8. THE API endpoint SHALL verify that the user owns the conversion before allowing deletion
9. THE API endpoint SHALL return 403 Forbidden if the user does not own the conversion
10. THE API endpoint SHALL delete the conversion record from the database when deletion is confirmed

### Requirement 18: Improve Search and Filter Placeholder Visibility

**User Story:** As a user, I want to clearly see the placeholder text in search and filter inputs, so that I understand what each input is for.

#### Acceptance Criteria

1. THE search input placeholder text SHALL be visible with sufficient contrast (minimum WCAG AA contrast ratio of 4.5:1)
2. THE "All Types" filter dropdown placeholder SHALL be visible with sufficient contrast
3. THE "All Status" filter dropdown placeholder SHALL be visible with sufficient contrast
4. THE placeholder text color SHALL be changed from light gray to a darker gray (e.g., #6B7280 or darker)
5. THE placeholder text SHALL remain distinguishable from actual input values
6. THE placeholder text SHALL be readable on both light and dark backgrounds

### Requirement 19: Remove Horizontal Scrollbar from Website

**User Story:** As a user, I want the website to fit within my viewport without horizontal scrolling, so that I have a better browsing experience.

#### Acceptance Criteria

1. THE website SHALL NOT display a horizontal scrollbar on desktop viewports (1024px and wider)
2. THE website SHALL NOT display a horizontal scrollbar on tablet viewports (768px to 1023px)
3. THE website SHALL NOT display a horizontal scrollbar on mobile viewports (below 768px)
4. ALL page elements SHALL fit within the viewport width without causing overflow
5. THE Conversion_History component SHALL not cause horizontal overflow
6. THE navigation bar SHALL not cause horizontal overflow
7. THE footer SHALL not cause horizontal overflow
8. WHERE content is too wide for the viewport, THE website SHALL use responsive design techniques (wrapping, stacking, or scrolling within containers) instead of causing page-level horizontal scroll
